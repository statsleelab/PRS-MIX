Theory walkthrough

Why the Null Simulation Draws Correlated Noise

The math behind simulate_null_gwas.R, mapped line by line onto the variables actually in the script — read this side by side with the code.

📄 inst/scripts/simulate_null_gwas.R
1

What the script is asked for

The script's four required arguments set up the whole simulation: panel_dir (an already-built LD reference panel), chr (which chromosome), n_gwas (the GWAS sample size to simulate under), and output_path (where the fake sumstats file goes). seed controls the random draw, so re-running with a different seed gives a different noise realization of the same null.

The goal: produce a file that looks exactly like a real GWAS summary-statistics file — one row per SNP with BETA and P — except every number in it is, by construction, pure noise. No SNP in this file has a real effect on anything.

2

Where the correlation structure comes from

panel_dir isn't just a source of allele frequencies — it supplies the thing that makes this simulation realistic: the actual, measured correlation between nearby SNPs in a real population.

simulate_null_gwas.R
# one block of nearby SNPs at a time
snplist <- blk[["snplist"]]$read()
R      <- as.matrix(blk[["ldblk"]]$read())
maf    <- maf_by_snp[snplist]

R is read straight out of the panel's HDF5 file — it was computed earlier, from real genotypes, when the reference panel itself was built. This script doesn't estimate LD; it borrows it.

Why this matters

Every SNP-to-SNP correlation this simulation will contain is already baked into R before a single random number is drawn. Get R right and the simulated noise behaves like real noise; the rest of the script is just a way of "unpacking" R into an actual random sample.

3

Why plain independent noise is the wrong null

Nearby SNPs travel together across generations, so their genotypes are correlated across any real population. That has a direct statistical consequence: if you regress a trait that has zero true relationship to genotype against two correlated SNPs, the two resulting noise-only effect estimates come out correlated too — Cov(beta_i, beta_j) ∝ r_ij, even though nothing real is happening in either one.

Drawing each SNP's fake effect independently throws that fact away. It produces a null dataset that no real experiment would ever generate — too clean, and not a fair test of whether a method's use of LD is actually correct.

4

Generating a vector with a chosen correlation: Cholesky

There's a standard way to turn independent random numbers into correlated ones with an exact target correlation matrix. If w is a vector of independent standard normals, its covariance is just the identity matrix — no correlation. Transform it linearly, z = A·w, and the covariance of the result becomes A·Aᵀ (the superscript T is matrix transpose). So the whole problem reduces to: find a matrix A such that A·Aᵀ = R.

The Cholesky decomposition is exactly that: it factors R into an upper-triangular matrix U such that R = Uᵀ·U. Setting A = Uᵀ finishes the job.

simulate_null_gwas.R
# z ~ MVN(0, R): draw iid standard normal w, apply R's upper-triangular
# Cholesky factor U (R = t(U) %*% U) so that Cov(t(U) %*% w) == R.
U <- chol(R)
w <- stats::rnorm(m_snps)
z <- as.vector(crossprod(U, w))

Checking the covariance confirms it works out exactly, with every variable named as it appears above:

Cov(z) = Cov( UT w )
= UT · Cov(w) · U
= UT · I · U (w is iid standard normal, so Cov(w) = I)
= UT U
= R (that's exactly how chol() defines U)
Intuition

Build z one entry at a time. The first entry is plain independent noise. The second reuses that same noise plus one new independent piece, blended with a weight tuned so the two entries end up correlated by exactly the right amount. The third reuses both earlier pieces plus one more new one, weighted to match both of its correlations at once — and so on. That "reuse everything before you, add one new independent source" pattern is precisely what the triangular shape of U encodes: crossprod(U, w) is just that recipe applied to w all at once.

Cholesky only exists for a matrix that could plausibly be a real covariance matrix (technically: positive semi-definite). That's why the panel-building pipeline already pushes each block's raw empirical correlation matrix through an eigenvalue floor before it's ever saved as ldblk — without that step, chol(R) could fail outright on a block estimated from too few samples.

5

Turning a z-score into a GWAS row

z is on a standardized scale. PRS-CS expects a per-allele BETA and a two-sided P, so the script converts using the standard GWAS relationship between a SNP's effect size, its standard error, and the sample size:

simulate_null_gwas.R
p    <- 2 * stats::pnorm(abs(z), lower.tail = FALSE)
se   <- 1 / sqrt(2 * n_gwas * maf * (1 - maf))
beta <- z * se

The se formula comes from how much a genotype varies in the population: a dosage of 0/1/2 copies has variance 2·maf·(1−maf) under random mating, and a regression's standard error shrinks with both the sample size and the predictor's variance — more samples or more genetic variation at that SNP both mean a more precise (smaller) se. Multiplying the standardized z back through se lands beta on the same per-allele scale a real GWAS would report, and p is derived from that same z, so the two columns are always mutually consistent.

6

One block at a time, then stitched together

The whole procedure above runs inside a loop over blk_names — the panel's LD blocks, each one a self-contained chunk of nearby SNPs. A block with fewer than 2 SNPs (m_snps < 2) is skipped outright, since there's no pair to correlate. Every block's result lands in out_parts, and those get stacked into one table (out) at the end and written to output_path.

Correlation is only ever simulated within a block, never across blocks — matching the block-diagonal approximation the reference panel itself already makes (SNPs far enough apart on the chromosome are treated as uncorrelated). The simulated null inherits exactly the same LD approximation the real panel uses, nothing more.
